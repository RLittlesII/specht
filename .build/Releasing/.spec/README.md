# Specification: Release

## 1. Business Goal

<!-- last written by: spec-author, 2026-10-08 -->

Nothing publishes `specht.tool`: `0001-F2` § 5 row 7 hands the release workflow to repository tooling that does not exist, so the first package would be pushed by hand from one machine, with no proof that what was pushed is what the gates checked - and the first package is the one that freezes schema version 1 for every consumer (`0001-F7` decision 0002). This Feature removes that failure state: pushing a `v*` tag runs the full build on the tagged commit, publishes the package to GitHub Packages on `rlittlesii/specht` only if every gate passed, and creates a GitHub Release for the tag; nothing else publishes.

## 2. User Needs

<!-- last written by: spec-author, 2026-10-08 -->

| #   | Persona                         | Need                                                               | Pain Point Today                            |
| --- | ------------------------------- | ------------------------------------------------------------------ | ------------------------------------------- |
| 1   | The maintainer                  | A release is one tag, and a failed gate publishes nothing          | No release path exists                      |
| 2   | A consumer                      | A published package is exactly what passed the gates on its commit | A hand-pushed package carries no such proof |
| 3   | A consumer reading what changed | A GitHub Release per published version                             | Nothing marks a version                     |
| 4   | `0055-F7`                       | A package on the feed to install                                   | N/A (internal dependency)                   |

### Assumptions

| ID  | Assumption                                                                                                                                      |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| A-1 | The release workflow is generated by the NUKE build, as the CI workflow is (`0055-F2` C-1); `specht-conventions` § Layout names it beside `ci`. |
| A-2 | The tag is created by `nbgv tag` (`0055-F5` B-007), so its name and the computed version agree unless someone types a tag by hand.              |

## 4. Constraints

<!-- last written by: spec-author, 2026-10-08 -->

| ID  | Constraint                                                                                                                                                                                                                                                                                | Rules Out                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| C-1 | A package reaches a feed only through a pushed `v*` tag and this Feature's run.                                                                                                                                                                                                           | A publish from a push to `main`, a pull request, a manually triggered run or a developer's machine.                      |
| C-2 | The first `v*` tag is pushed only after `0001-F5` and `0001-F6` have landed, because the first published package freezes schema version 1 (`0001-F7` decision 0002).                                                                                                                      | A tag pushed to try the pipeline (B-008 is the trial); a prerelease publish before then - any publish freezes version 1. |
| C-3 | GitHub Packages on `rlittlesii/specht` is the only feed.                                                                                                                                                                                                                                  | Publishing to NuGet.org, which README § 2 records as the reversal, not a second target.                                  |
| C-4 | The published package is the file `Pack` wrote in the same run.                                                                                                                                                                                                                           | A package rebuilt, re-versioned or fetched from another run between the gates and the push.                              |
| C-5 | The workflow's own token, granted package write for the run, is the only publishing credential (owner, 2026-10-08).                                                                                                                                                                       | A stored publishing token or personal access token as a repository secret.                                               |
| C-6 | `SpecCheck` gates a release or a dry run only from `0001-F2`'s check command landing; until then its step reports itself unavailable and passes, and `SPEC060` is a warning here (`0055-F1` B-023, B-024, C-6, C-7; owner, 2026-10-08). The first tag follows `0001-F2` regardless (C-2). | A release or dry run failed because the check command does not exist yet, or for a `Missing` traceability row.           |
