# Decision 0001: withdraw the stale-workflow check

**Date:** 2026-10-09
**Decided by:** the repository owner, 2026-10-09; recorded by spec-author

## The call

- B-009 is withdrawn: no run fails because a committed generated workflow
  differs from what the build generates. Its number stays retired.
- C-1 is unchanged: every workflow is generated by the NUKE build, never
  hand-edited, and a change to one commits the regeneration with the build
  change.
- Item 0065, which would have built the check, is retired; its file is
  deleted and cited at commit `92890af`.
- `0055-F4` B-013 and B-014, which existed so B-009 would pass on an update
  pull request, are re-grounded on C-1. Their behaviour does not change.

## Why

The owner, 2026-10-09: "We don't need this. If we are not smart enough to
check in the associated yml with a change, that's a PEBKAC problem! I am all
for building in safeguards. This is EXCESSIVE."

Committing the regeneration is part of the change C-1 already requires of its
author. A run-time check guards a step the author is already obliged to take.

## Rejected

**Keeping B-009 as resolved under OQ-1 (2026-10-08).** A run would fail on a
stale committed workflow. Cost of rejecting: a build change committed without
its regeneration is caught only by review, or by the next build run that
regenerates the file and shows a diff.

## Affects

- B-009 (Withdrawn); OQ-1 (resolution reversed); C-1 (unchanged).
- `0055-F4` B-013 and B-014 (Source re-grounded on C-1).
- Items 0063, 0064 and 0075; item 0065 retired.

## Reversal

None.
