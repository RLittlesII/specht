# SPEC2003: A companion file sits beside a specification

## Metadata

| Property         | Value     |
| ---------------- | --------- |
| Rule ID          | SPEC2003  |
| Family           | Structure |
| Default severity | Warning   |
| Schema version   | 0.4.0     |

## Cause

A file one of the manifest's `companionFiles` globs matches sits in a directory where a layout would find a specification, and no specification of any layout is in that directory. Reported once per file, with no line:

| Condition                           | Message                                            |
| ----------------------------------- | -------------------------------------------------- |
| A companion beside no specification | `no specification sits beside this companion file` |

## Rule description

A layout's directory part is its glob with the final segment removed: `**/.spec/README.md` gives `**/.spec`, and `epics/**/spec.md` gives `epics/**`. Each directory part joined to each companion glob is where a companion is looked for, outside `exclusions`; the default manifest looks for `epics/**/*.feature` and `**/.spec/*.feature`. A companion found there is reported unless a specification of any layout is in the same directory. A `.feature` file anywhere else, such as under `test/`, is not reported.

### Example violation

```text
src/orders/.spec/orders.feature
```

```text
src/orders/.spec/orders.feature: warning SPEC2003: no specification sits beside this companion file
```

### Corrected

```text
src/orders/.spec/README.md
src/orders/.spec/orders.feature
```

## How to fix violations

- **The specification is missing.** Write the specification beside the companion.
- **The specification moved.** Move the companion with it.
- **The file is not a companion.** Move it out of the specification directory, or add its directory to `exclusions`.
