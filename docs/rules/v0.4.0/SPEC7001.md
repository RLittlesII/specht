# SPEC7001: A done specification has no missing coverage

## Metadata

| Property         | Value    |
| ---------------- | -------- |
| Rule ID          | SPEC7001 |
| Family           | Approval |
| Default severity | Error    |
| Schema version   | 0.4.0    |

## Cause

A Feature specification's delivery `status` is the done value and a cell of its matrix table is exactly the missing marker, whatever its `spec_status`. The manifest sets all three:

| What               | Manifest key      | Default manifest            |
| ------------------ | ----------------- | --------------------------- |
| The done value     | `markers.done`    | `done`                      |
| The missing marker | `markers.missing` | `Missing`                   |
| The matrix section | `roles.matrix`    | `## 9. Traceability Matrix` |

Reported once per such row, at the row, in fixed text whatever the manifest gives:

`status is 'done' while § 9 still carries a 'Missing' cell`

## Rule description

A done Feature's matrix has no `Missing` cell. A `Missing` cell does not block `spec_status` reaching approved: under any other delivery `status`, `Missing` cells are not reported. Schemas `0.1.0` to `0.2.1` report an approved specification instead, whatever its delivery `status`.

### Example violation

A specification with `status: done` and this § 9 row:

```markdown
| B-002 | A total is the sum of its lines | Missing | Missing |
```

```text
src/orders/.spec/README.md(74): error SPEC7001: status is 'done' while § 9 still carries a 'Missing' cell
```

### Corrected

```markdown
| B-002 | A total is the sum of its lines | `OrderTests.SumsLines` | Covered |
```

## How to fix violations

- **The test exists.** Replace `Missing` in the row with the test and its status.
- **The test does not exist.** Write it, or set `status` back to `in-progress`.
- **The repository does not hold delivery to coverage.** Lower the rule in the manifest's `rules`.
