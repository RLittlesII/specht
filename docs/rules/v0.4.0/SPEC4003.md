# SPEC4003: Claim ids are well formed and unique

## Metadata

| Property         | Value    |
| ---------------- | -------- |
| Rule ID          | SPEC4003 |
| Family           | Claims   |
| Default severity | Error    |
| Schema version   | 0.4.0    |

## Cause

The first cell of a row in the claims table is not a usable claim id, or a Feature's claim prefix gives its claims the scenario head. The claims section is the one the manifest's `claims` role names, `## 3. Acceptance Criteria` in the default manifest; the message says § 3 whatever its title.

| Condition                                                                         | Reported at      | Message                                                                                                                                              |
| --------------------------------------------------------------------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| The id does not match the grammar                                                 | the row          | `claim id '{id}' does not match {grammar} - claim ids are permanent, so the form is fixed`                                                           |
| The id does not match the Feature's head                                          | the row          | `claim id '{id}' does not match the claim prefix '{head}' followed by a whole match of ids.claim.id - claim ids are permanent, so the form is fixed` |
| The id's text after the claim head begins with the rest of a longer scenario head | the row          | `claim id '{id}' begins with the scenario head '{scenarioHead}', so its tag would read as a scenario tag`                                            |
| The Feature's prefix gives claims and scenarios one head                          | the prefix's key | `claim_prefix gives claims and scenarios the one head '{head}', so the Feature is read as declaring no prefix`                                       |
| The id is also that of an earlier row                                             | the row          | `claim '{id}' is declared twice in § 3 (also at line {line})`                                                                                        |

The grammar comes from the manifest's `ids.claim` record. For a Feature that declares no claim prefix, under the key the manifest's `keys.feature.claimPrefix` names, `claim_prefix` by default, the head is the record's `plain` without its closing `{id}`, `B-` in the default manifest; for a Feature that declares one it is the record's `form` with the prefix in place of `{prefix}`, the prefix itself in the default manifest. The grammar is the head as literal, case-sensitive text followed by a whole match of the record's `id`; `{grammar}` is that pattern, `^B-(?:[0-9]{3}[a-z]?|[0-9a-hjkmnp-tv-z]{6}|[0-9a-hjkmnp-tv-z]{13})$` in the default manifest.

The scenario head is rendered the same way from `ids.scenario`, `S-` in the default manifest. A prefix whose claim head equals its scenario head, compared as `claim.tagIgnoreCase` compares tags, is reported once and the Feature's claims are read as if it declared none. Where the scenario head is longer than the claim head and begins with it, a claim id whose text after the claim head begins with the rest of the scenario head is reported, since its tag would read as a scenario's.

## Rule description

Each claim id is its Feature's claim head followed by a whole match of `ids.claim.id` - by default `B-`, or the Feature's own claim prefix, then three digits and an optional lowercase letter or six or thirteen base32 characters - is declared once in its specification, and cannot be read as a scenario tag.

### Example violation

```markdown
| B-2 | An order total is the sum of its lines. | need 1 | Active |
```

```text
src/orders/.spec/README.md(43): error SPEC4003: claim id 'B-2' does not match ^B-(?:[0-9]{3}[a-z]?|[0-9a-hjkmnp-tv-z]{6}|[0-9a-hjkmnp-tv-z]{13})$ - claim ids are permanent, so the form is fixed
```

### Corrected

```markdown
| B-002 | An order total is the sum of its lines. | need 1 | Active |
```

## How to fix violations

- **Malformed.** Rewrite the id in the grammar's form, and its scenario tags and § 9 row with it.
- **Scenario head.** Choose a claim prefix whose claim head differs from its scenario head, or a claim id that does not begin with the scenario head.
- **Declared twice.** The later claim takes the next unused number; the earlier one keeps its id.
