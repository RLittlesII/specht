# SPEC4010: Every matrix status is borne out

## Metadata

| Property         | Value    |
| ---------------- | -------- |
| Rule ID          | SPEC4010 |
| Family           | Claims   |
| Default severity | Error    |
| Schema version   | 0.4.0    |

## Cause

A § 9 row's Status says something its scenario and its tests do not bear out, or is none of the six status markers. The diagnostic names the claim at its matrix row.

| Condition                                                                             | Message                                                                                                                |
| ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Covered, and the scenario does not resolve                                            | `§ 9 status 'Covered' overclaims: its scenario does not resolve`                                                       |
| Covered, and the Test cell names no test in inline code                               | `§ 9 status 'Covered' overclaims: its Test cell names no test in inline code`                                          |
| Covered, and a named test does not resolve                                            | `§ 9 status 'Covered' overclaims: a test it names does not resolve`                                                    |
| Partial, and neither the scenario nor any named test resolves                         | `§ 9 status 'Partial' overclaims: neither its scenario nor any test it names resolves`                                 |
| Missing, and the Test cell names tests that all resolve                               | `§ 9 status 'Missing' is stale: every test it names resolves`                                                          |
| The Status is none of the covered, partial, missing, waived, withdrawn and superseded | `§ 9 status '{status}' is not a marker; expected 'Covered', 'Partial', 'Missing', 'Waived', 'Withdrawn', 'Superseded'` |

## Rule description

The matrix columns are read by position from `tables.matrix`: claim, scenario, test, status, and every status is compared with the markers the manifest gives. A row's scenario resolves when the claim's tag, `claim.tag` around its id under `claim.tagIgnoreCase`, is on any tag line of the companion, above a `Rule:` or the `Feature:` included; with `matrix.scenarioTitles` on, every `;`-separated title of the Scenario cell must also name a scenario carrying that tag, and a cell naming no title does not resolve. A test name resolves as `SPEC4009` resolves it.

With no `tests` key no test name resolves or fails: a covered row needs its scenario and a test named in inline code, a partial row its scenario, and a missing row is never stale. A waived, withdrawn or superseded row is not judged here. A row `SPEC4008` would report, a live claim no companion tag carries at a row that is neither missing nor waived, is left to it, whatever level `rules` gives `SPEC4008`.

### Example violation

The manifest declares `"tests": { "files": ["test/**/*.cs"] }`, the companion carries `@B-001`, and `test/` holds `RejectsAnEmptyOrder`.

```markdown
| B-001 | An empty order is rejected | `RejectsAnEmptyOrder` | Missing |
```

```text
src/orders/.spec/README.md(43): error SPEC4010: § 9 status 'Missing' is stale: every test it names resolves [B-001]
```

### Corrected

The test exists, so the row is covered:

```markdown
| B-001 | An empty order is rejected | `RejectsAnEmptyOrder` | Covered |
```

## How to fix violations

- **Overclaimed.** Tag the scenario, name and add the tests, or lower the Status to the partial or the missing marker.
- **Stale.** Raise the Status to the covered marker once the scenario and tests are in place.
- **Not a marker.** Write one of the six markers the manifest gives.
