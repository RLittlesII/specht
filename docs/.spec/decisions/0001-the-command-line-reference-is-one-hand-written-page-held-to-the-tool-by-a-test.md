# Decision 0001: The command-line reference is one hand-written page, held to the tool by a test

**Date:** 2026-10-11
**Decided by:** the repository owner, on three questions put the same day and in a plan approved the same day; what is marked spec-author's below was not put to the owner

## The call

The owner, 2026-10-11, on the command-line documentation:

> I think the command matrix in the README is horrible as well. I think we
> should clearly demonstrate the full api surface.

Asked three questions, the owner chose:

1. **Where it lives:** "One docs/cli.md page". One reference page under the
   root `docs/`, every command and option on it; `README.md` keeps a short
   synopsis and links to it (B-003, B-006, B-007, B-011, C-6). This resolves
   OQ-2.
2. **How it is kept true:** "Hand-written, test-pinned". The page is written by
   hand, and a test runs each command's `--help` and fails when a command or
   option is missing from the page, or extra in it (B-006 to B-008, C-7).
3. **Commands specified and not built** (`upgrade`, `--explain`, `--report`,
   `manifest`, `rules`): "Remove until built". The reference and both readmes
   show only what the shipped tool accepts, and each command's delivering pull
   request adds its own section (B-008 to B-010, C-8, § 5 row 6).

The owner also approved, 2026-10-11, the delivery plan, one step of which
reads:

> `AGENTS.md` § CLI: mark `upgrade`, `--explain` and `--report` as specified
> and not built, as it already does for `manifest` and `rules`

So that one statement in `AGENTS.md` § CLI is the owner's, and item 0181
makes it (§ 5 row 7, amended).

Spec-author's, on those answers:

- **"Accepts" is what the tool's help lists** (A-6): the default command, each
  command the root help lists, and each option a command's help lists,
  `--help` included. It is what the owner's test reads.
- **"Names" is a command or option shown in code formatting** (A-7), so a
  sentence about a future command is not a failure and a command line is.
- **The readme's link is a claim** (B-011), since the owner's first answer
  states it.
- **"Missing from, or extra in" is three claims**: a command with no section
  (B-006), an option with no entry (B-007), and anything on the page the help
  does not list (B-008). Each fails for one reason.
- **The skills, and `AGENTS.md` beyond that one statement, are left as they
  are** (§ 5 row 7). The owner named the reference, both readmes and the
  § CLI statement.

## Why

- `README.md` and `src/tool/README.md` list `--report <path>`,
  `specht upgrade` and `--explain`, and `src/tool` accepts none of them. The
  tool accepts `specht [--root <DIR>] [--strict] [--json]` and
  `specht init [--root <DIR>]`.
- B-003 placed a usage doc in each command folder at a location OQ-2 had not
  named, so nothing could be written against it.
- A test over the help is a check the build runs; review alone is what let the
  readmes drift.

## Rejected

All three sets were put to the owner and turned down.

**Where it lives**

- **One page per command under `docs/cli/`.** Cost of rejecting: the one page
  grows with every command.
- **A usage doc beside each command, `src/tool/Features/<Command>/USAGE.md`.**
  What B-003 said before. Cost of rejecting: the doc is no longer in the
  folder a command's pull request already edits; C-5 and the test carry that
  instead.
- **Everything in `README.md`.** Cost of rejecting: a reader follows one link
  from the front page.

**How it is kept true**

- **Generated by a NUKE target.** Cost of rejecting: the page is typed by
  hand, and the test checks that a command or option is present, not that its
  prose is right.
- **Verbatim `--help` blocks compared byte for byte.** Cost of rejecting: a
  reworded option description in the code does not fail the page.
- **Hand-written, with review only.** Nothing is lost by rejecting it.

**Commands specified and not built**

- **Keeping them on the page.** Cost of rejecting: a reader of the reference
  does not learn what is coming; the specifications say it.

## Command branches 2026-10-14

The schema branch adds the first nested commands. The help-derived surface
recurses through command branches, including each branch and leaf, so B-006
to B-008 continue to cover every shipped command. The command-line reference
remains one hand-written page. This is the schema-command implementation's
application of the existing help-derived contract, not a new command source.
