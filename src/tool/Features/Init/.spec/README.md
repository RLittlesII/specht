# Specification: init

## 1. Business Goal

<!-- last written by: spec-author, 2026-10-07 -->

A repository adopting the model copies `hooked`'s `.spec/schema/` and `.spec/templates/` by hand, from whatever day it looked, and nothing records which day. This Feature removes that failure state: `specht init` writes the schema set and the templates from copies embedded in the tool, so every consumer starts from the same bytes as this repository, and the copy is a fact of the tool version rather than of a day. It never overwrites, so a repository that already has a file keeps it.

## 7. Technical Design

<!-- last written by: implementer, 2026-10-10 -->

**The shipping copy (B-004, B-005, C-2).** `src/tool/schema/v<n>/` holds the four schema files (`spec-structure.schema.json` and the three frontmatter schemas) and `src/tool/templates/v<n>/` the four templates (`feature.md`, `decision.md`, `adr.md`, `lesson.md`); `item.yml` is not shipped. `tool.csproj` embeds them under the logical names `schema/v<n>/<file>` and `templates/v<n>/<file>`, `/`-separated on every OS. The newest version is the highest `<n>`. `v1` is a byte copy of the live `.spec/`.

**The writer (B-001, B-003, B-006, B-008, B-010; C-1, C-3, C-4).** `InitWriter` (`Features/Init/InitWriter.cs`) takes the shipping copy as a name-to-bytes map and an `IFileSystem`. `InitWriter.ShippingCopy(Assembly)` builds the map from the resources whose names match `^(schema|templates)/v<n>/<file>$`; other resources are ignored. `Write(root, cancellationToken)`:

- throws `SpechtRootNotFoundException`, the engine's, before touching anything when the root is not a directory, so `init` never creates the root itself (C-3);
- keeps the entries with the highest `<n>`, compared as integers so `v10` outranks `v2`, and maps each to `.spec/<folder>/<file>`, dropping the version (B-001);
- for each, in ordinal order of that relative path: an existing file is listed skipped and not opened (C-1); an absent one has its folder created (with `.spec/` if absent, C-3) and is written with `FileMode.CreateNew`, so a file created between the check and the write fails the run rather than being overwritten, then listed written;
- writes the bytes as embedded, with no transformation (B-003).

It returns `(Path, Written)` pairs whose paths are already root-relative with `/`, so nothing absolute reaches stdout (C-4). The map, not the `Assembly`, is the constructor argument, so a unit test hands it two versions before a second one ships.

**The command.** `InitCommand` (`Features/Init/InitCommand.cs`) is an `AsyncCommand` with nested `Settings`: `--root <DIR>`, defaulting to `.` (B-009). It resolves the root with `Path.GetFullPath`, as `CheckCommand` does, calls the writer, and writes one line per file, `written <path>` or `skipped <path>`, through the console's raw `Profile.Out.Writer` so a line is never wrapped. It returns `ExitCodes.Success` after the listing, whatever was skipped (B-011); the writer's loop decides each file on its own, so a partial tree gets each absent file (B-010). A root that is not a directory is folded into `ExitCodes.MissingInput` with `specht: '<root as typed>' is not a directory.` on stderr, echoing `settings.Root` and not the resolved root (B-007, C-4); the writer has thrown before touching anything, so nothing is written (C-3). Stderr is written with `Console.Error`, as the check's is (`0001-F2` § 7), and is not injected: the command tester cannot capture it, so the echo as typed is asserted only by the scenario (§ 8). An injected error writer is the open seam, not built.

**Not built, as of 2026-10-10.** The command has no `--epics` and the writer reads no manifest, so every run's set is the eight files of the newest version, whatever a manifest beside them says. Leaving an existing file alone is built (C-1), and B-002's proof is `0054`'s, with the pin (B-012, B-013). An upstream schema source (B-014 to B-016) is `0095`. A rejected manifest (B-017) is `0096`. The `schemaVersion` the written manifest carries (`0001-F7` B-012) is `0049`. The epic choice - `--epics` into a bare root, the manifest's epic grammar beside an existing manifest (B-018 to B-023; C-5, C-6; OQ-2) - has no item.

**The composition root.** `Program.cs` registers `InitWriter` as a singleton built from `InitWriter.ShippingCopy(typeof(InitWriter).Assembly)` and `new FileSystem()`, and adds `init` with `AddCommand` beside the default `CheckCommand`, so `specht --root <dir>` still reaches the check. `TestableIO.System.IO.Abstractions.Wrappers` reaches the tool through its reference to the engine; no package is added.

The engine's default manifest (`src/specht/specht.csproj`, `specht.default-manifest.json`) stays a link to the live `.spec/schema/spec-structure.schema.json`, not a third copy (C-2). Drift between the shipping copy and the live copy is caught by the B-004 tests, not by a build step that generates one from the other (C-2).

## 8. Testing Strategy

<!-- last written by: test-writer, 2026-10-10 -->

- **The seams.** The `ShippingCopy` tests and B-004's steps read the shipping copy straight from the `specht.tool` assembly, `typeof(ExitCodes).Assembly`, through `GetManifestResourceNames` and `GetManifestResourceStream`; the newest version is the highest `<n>` among the `schema/v<n>/` names. `InitWriter` (§ 7) takes the shipping copy as a name-to-bytes map and an `IFileSystem`, so its unit tests hand it any set of versions over a `MockFileSystem` with the repository-relative root `repo`; `InitCommand` takes the writer injected, so a command test runs it through `CommandAppTester`. The live copy is this repository's `.spec/schema/*.json` and `.spec/templates/{feature,decision,adr,lesson}.md`, which each test project copies into its output; `item.yml` is not copied.
- **Unit** (`test/tests/ShippingCopy.Unit.Tests.cs`):
  - A-1 - mechanism: the logical names `tool.csproj` gives the embedded files. `TheNewestEmbeddedVersion_WhenListed_ShouldHoldExactlyTheEightFiles` asserts that the newest version's `schema/v<n>/` and `templates/v<n>/` names are exactly the eight files.
  - B-005 - mechanism: the `$id` each embedded frontmatter schema carries, which `init` will write unchanged (B-003). `TheNewestEmbeddedFrontmatterSchema_WhenRead_ShouldCarryAnIdUnderThisRepositorysSchemaAddressForItsVersion` has one row per frontmatter schema and asserts `https://github.com/rlittlesii/specht/schema/v<n>/<file>`. The @B-005 scenario proves `init` writes it.
- **Unit** (`test/tests/InitWriter.Unit.Tests.cs`, written by `implementer` with 0052's code), the writer over a `MockFileSystem`:
  - `AShippingCopyOfSeveralVersions_WhenWritten_ShouldWriteOnlyTheHighestNumberedVersion` - the newest-version choice, compared as integers (`v10` over `v2`) (B-001).
  - `AnEmbeddedName_WhenWritten_ShouldLandUnderItsFolderInDotSpecWithItsBytesUnchanged` - the map from `schema|templates/v<n>/<file>` to `.spec/schema|templates/<file>`, root-relative with `/`, and the bytes written unchanged, a BOM and CRLF included (B-001, B-003, B-008, C-4).
  - `AFileThatExists_WhenWritten_ShouldBeListedSkippedAndLeftAsItWas` - the written-or-skipped choice (B-006, C-1).
  - `TheEmbeddedShippingCopy_WhenWrittenIntoABareRoot_ShouldWriteTheEightFilesAndNothingOutsideTheTwoFolders` - the real embedded copy yields exactly the eight files, all under the two folders (B-001, B-008, C-3).
  - `ARootThatIsNotADirectory_WhenWritten_ShouldThrowRootNotFoundAndCreateNothing` - the writer refuses a root that is not a directory before touching anything, and never creates it (B-007, C-3).
  - `SomeFilesPresentAndOthersAbsent_WhenWritten_ShouldWriteEachAbsentOneWithItsShippedBytes` (written by `test-writer` with `0053`) - the choice is made file by file: with one of four shipped files present, each of the other three is on the file system with its shipped bytes, the one that sorts after the present file included (B-010). The test above it asserts the listing and the present file, not that an absent file reached the file system.
- **Integration** (`test/tests/ShippingCopy.Integration.Tests.cs`), B-004 - mechanism: a byte copy for the tool-owned files, and the subset equality of the manifest, whose tool-owned keys are the top-level keys the embedded manifest carries. `TheNewestEmbeddedFile_WhenComparedWithTheLiveCopy_ShouldBeByteIdentical` has one row per frontmatter schema and template. `TheNewestEmbeddedManifest_WhenComparedWithTheLiveManifest_ShouldEqualItOnEveryKeyTheEmbeddedManifestCarries` asserts that each embedded key is present in the live manifest and equal under `JsonNode.DeepEquals`; a key only the live manifest carries is outside the comparison. These tests are Integration because they read the live files from disk. Assertion messages carry repository-relative paths only.
- **Acceptance.** `init.feature` is linked into `test/acceptance`; [`Init/InitSteps.cs`](../../../../../test/acceptance/Init/InitSteps.cs) binds B-004 to B-011, and its scenarios run and pass. B-004 reads the live manifest, adds a synthetic `rules` setting lowering `SPEC031` to warning in memory, and asserts that the comparison still holds. The others launch the built tool through `Tool.Launch` over a synthetic root, `repo/` inside a fresh temporary sandbox seeded with a `README.md`, a `.spec/README.md` and a file beside the root. `init --root repo` runs from the sandbox, so a write beside the root is caught (B-008), and a bare `init` runs from the root (B-009). The B-008 step also requires that `init` created something, so a run that does nothing cannot pass it. B-005 is bound because at a bare root it follows directly from B-003 and the `$id` the unit test pins: the version written is the newest. B-007's sandbox holds a file and no root: the Given types the root `./no-such-root`, relative to the sandbox, and snapshots the sandbox. Its outcome steps hold stderr to that text as typed and to not naming the sandbox (C-4), the sandbox to the snapshot, and the root to still not existing (C-3).
