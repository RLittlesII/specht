# Specification: Comment size

## 1. Business Goal

<!-- last written by: spec-author, 2026-11-06 -->

An agent amending a specification can leave a comment that narrates the amendment: a banner, a dated list of what changed and what it buys, beside content that already says what is true now. The narrative repeats the commit and § 10, grows with each amendment, and nothing reports it, because the check reads no comment. This Feature removes that failure state for a repository that asks for it: under a manifest that sets its key, the check warns, on the comment's opening line, for each comment in a Feature specification that spans more lines or holds more characters than the manifest's limits. A stamp is never judged, a one-line marker stays within the limits, and no comment is asked to say who, when or why.

| OQ-1 | What is the key, and what shape does it take? Proposed: a top-level `comments` object, `{ "maxLines": 1, "maxCharacters": 200 }`; setting it turns the rule on, each member is optional and takes its default when left out, and an empty object takes both.
