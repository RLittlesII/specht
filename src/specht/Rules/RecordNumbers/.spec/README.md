# Specification: Record number uniqueness

## 1. Business Goal

<!-- last written by: spec-author, 2026-10-09 -->

A decision, an ADR or a lesson is cited by its number: `0001-F5` decision 0003, `ADR-0004` and lesson 0005 must each name one file. Two branches cut from the same trunk each take the next free number in a record folder, and git merges both files without a conflict, because their names differ after the number ([lesson 0005](../../../../../.spec/lessons/0005-an-id-is-not-reserved-until-it-merges.md), where `0001-F5` decision 0003 was written three times). The check says nothing: schema version `0.1.0` reads no record folder. A citation of the doubled number then names two records, and only a reader finds it. This Feature removes that failure state: from the major schema version that adds this rule (OQ-3), the check reports, as an error, each number that two or more files in one `decisions/`, `adr/` or `lessons/` folder open with, beside a specification or repository-wide, on every claimant and with every claimant named.

## 2. User Needs

<!-- last written by: spec-author, 2026-10-09 (the owner's answers to OQ-2, OQ-5 part (b) and OQ-7 cited; no claim or constraint changed in what it requires) -->

| #   | Persona                                                    | Need                                                                      | Pain Point Today                                                                                                                                          |
| --- | ---------------------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Whoever follows a citation such as `0001-F5` decision 0003 | The number names exactly one record in its folder                         | Two files opening with one number pass the check, and the citation names both                                                                             |
| 2   | The agent merging two branches                             | Be told which number is claimed twice and by which files, from the report | Two records sharing a number merge cleanly; the clash is found by reading                                                                                 |
| 3   | The agent writing the next record                          | Not be handed a doubled number as the highest one in the folder           | The next number is read off a folder nothing has checked                                                                                                  |
| 4   | The reviewer of a pull request that adds a record          | Not carry each folder's numbers in their head                             | A record folder has no sequence file, and review is the only thing that enforces it ([`0128`](../../../../../.issue/0128-detect-an-id-claimed-twice.yml)) |
| 5   | The maintainer of four repositories                        | Lower or switch off the rule per repository                               | A tree written before the rule may already carry a doubled number                                                                                         |

### Assumptions

| ID  | Assumption                                                                                                                                                                                                                                                           |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A-1 | An error is printed, counted and fails the run; a manifest's rule settings lower a rule to a warning or disable it (`0001-F5` B-010, B-011).                                                                                                                         |
| A-2 | Record folders are found by discovery from what the manifest declares, as every other file shape is (`0001-F6` C-5); the names and shapes of the keys that declare them are OQ-8, and this specification names no key.                                               |
| A-3 | A record number is read through the manifest's record number grammar, as `0001-F5` C-2 requires of every rule.                                                                                                                                                       |
| A-4 | The major schema version that adds this rule (OQ-3) has not been published, so its rule vocabulary can still take it; a version freezes at its first publish (`0001-F7` decision 0002).                                                                              |
| A-5 | A record is append-only and is never deleted: a reversed decision gains a reversal and a superseded ADR changes its status, each keeping its file (`.spec/templates/decision.md`, `.spec/templates/adr.md`). A number once used therefore stays visible in the tree. |
