# SPCT0013: Ordinary comment on a declaration surface

| Property         | Value                       |
| ---------------- | --------------------------- |
| Default severity | Warning, enabled by default |
| Code fix         | None                        |

The analyzer reports each ordinary `//` comment on a CSharp class or method
declaration surface, at that comment's source span. It checks every accessibility,
nested and partial classes, and methods in any containing type. Surface material
includes leading comments and comments among attributes, modifiers and signature
tokens, ending before the body brace, expression-body arrow or semicolon.

`///` XML documentation remains allowed, including traceability-only tags. XML
documentation beside an ordinary comment does not hide the ordinary comment.
Documentation and summaries are not required by this rule.

```csharp
/// <spec epic="0004" feature="F1" />
internal static class StoreAccessSubstitute
{
}
```

Remove unnecessary declaration prose. Keep design reasoning in its specification
or decision record, and write useful API documentation as XML when appropriate.
There is no automatic deletion or conversion fix.

The rule excludes generated source, bodies, comments trailing completed
declarations, other declaration kinds and suppression-directive explanations.
An initial ordinary file-header block is excluded when an empty or whitespace-only
line separates it from the first following code or XML documentation. A blank
line above a method does not exempt its comment. Block comments are unchanged.

This source-local rule needs no manifest or specification records. Standard
Roslyn severity overrides and suppression apply, independently of traceability
input availability. Warnings-as-errors builds reject unsuppressed findings.
