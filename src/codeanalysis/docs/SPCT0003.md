# SPCT0003: Identifier violates the consumer grammar

| Property         | Value                            |
| ---------------- | -------------------------------- |
| Message          | The offending binding attributes |
| Default severity | Warning                          |
| Code fix         | Conditional target selection     |

## Finding and reporting conditions

A shaped reserved relationship has a complete identity, but its `epic`,
`feature`, `claim`, or `adr` value violates the consumer's configured grammar.
For example, `claim="B-001,B-002"` is one value and can violate a grammar that
accepts one claim ID. The diagnostic points to the `claim` or `adr` attribute
when present. In a selected project, explicit bindings are checked even outside
mandatory authoring scopes and in generated code.

## Configuration and resolution

Use the consumer's identifier settings and selected records, not a guessed
repository-wide ID form. Suppression leaves the binding invalid as evidence.
Correct the value. For safely replaceable XML, the code fix can offer eligible
targets from the supplied catalog; it offers no action when the XML or inputs
cannot be safely used. See the [package guide](../README.md) for configuration.
