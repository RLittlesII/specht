# SPCT0008: Partial type authoring defaults conflict

| Property         | Value                           |
| ---------------- | ------------------------------- |
| Message          | The offending `spec` attributes |
| Default severity | Warning                         |
| Code fix         | No                              |

## Finding and reporting conditions

One type has more than one shaped `<spec>` authoring default across its
declarations, and their attributes differ. For example, two parts of a partial
class declaring `<spec feature="F1" />` and `<spec feature="F2" />` both
receive this diagnostic. Identical defaults do not conflict. A conflicting
default cannot be used to complete a claim-only member relationship.

## Configuration and resolution

This check runs for explicit XML in a selected project with available consumer
inputs, including generated code. Make the type's defaults agree or remove the
unintended default. Standard Roslyn controls can change presentation; there is
no SPCT0008 code fix. See the [package guide](../README.md) for input selection.
