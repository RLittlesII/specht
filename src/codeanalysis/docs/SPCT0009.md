# SPCT0009: Duplicate valid relationship

| Property         | Value                                |
| ---------------- | ------------------------------------ |
| Message          | The repeated XML role and attributes |
| Default severity | Info                                 |
| Code fix         | Conditional duplicate removal        |

## Finding and reporting conditions

The same symbol has more than one valid, eligible relationship of the same
role to the same resolved target. For example, two identical
`<implements feature="F1" claim="B-001" />` elements produce a finding on
the later copy. The comparison uses resolved target identity; invalid or
ineligible elements do not count as duplicate evidence. This diagnostic is
informational by default.

## Configuration and resolution

Explicit relationships are checked in a selected project even outside
mandatory authoring scopes and in generated code. Roslyn severity overrides or
suppression do not change which relationship is valid. Remove redundant XML.
When the provider can find all copies in the current project, its code fix keeps
the first by root-relative path and source position and removes later copies;
it offers no action if an affected document is unavailable. See the
[package guide](../README.md) for input selection.
