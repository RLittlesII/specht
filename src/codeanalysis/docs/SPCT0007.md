# SPCT0007: Required authored relationship is missing

| Property         | Value                                                            |
| ---------------- | ---------------------------------------------------------------- |
| Message          | The declaration identity followed by `requires` and the XML role |
| Default severity | Warning                                                          |
| Code fix         | Conditional target selection for missing `verifies`              |

## Finding and reporting conditions

An enforcement scope selects a declaration and requires a `verifies`,
`implements`, or `follows` relationship, but no valid relationship of that role
is present. For example, a scope selecting recognized test methods for
`verifies` reports on a selected test method with no valid `<verifies>` element.
The diagnostic points to the declaration. A malformed or ineligible element
does not satisfy the requirement. Generated declarations require no authored
relationship, and there is no blanket requirement for shared infrastructure.

## Configuration and resolution

`codeAnalysis.enforcement` selects the project, source globs, declaration kinds,
and required role. A declaration exemption needs an explicit reason and removes
only its named requirement; it creates no evidence. Roslyn suppression does not
make the missing relationship present. Add an eligible relationship or adjust
the intended enforcement scope. The code fix currently offers target selection
only for a recognized ordinary test method missing `verifies`, with no existing
`<verifies>` element and eligible targets available. Other missing roles have no
automatic action. See the [package guide](../README.md) for policy inputs.
