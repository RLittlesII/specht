# SPCT0006: Resolved target is ineligible

| Property         | Value                            |
| ---------------- | -------------------------------- |
| Message          | The offending binding attributes |
| Default severity | Warning                          |
| Code fix         | Conditional target selection     |

## Finding and reporting conditions

A binding resolves to exactly one target, but that target is not eligible under
the consumer's lifecycle policy. A withdrawn or superseded claim is ineligible;
an ADR with an explicit lifecycle must be accepted. Feature and omitted-state
eligibility also follows the supplied policy. For example, an `<implements>`
element pointing to a withdrawn claim reports even though the claim exists.
Explicit bindings are validated in selected projects outside mandatory
authoring scopes and in generated code.

## Configuration and resolution

Bind to an eligible current target or correct the consumer record if its state
is wrong. Suppression does not turn an ineligible binding into evidence. The
code fix can offer eligible targets for safely replaceable XML when available;
it does not change lifecycle state. See the [package guide](../README.md) for
selected record inputs.
