# Decision 0005: the tree and its generator are engine code

**Date:** 2026-11-02
**Decided by:** the repository owner, for the move (pull request #114,
2026-10-11) and for the generator (2026-11-01, recorded 2026-11-02 on item
`0153`); spec-author, for where B-015 and B-016 are proven, which the owner may
reverse

## The call

- `SpechtTree`, `SpechtTreeFile`, `SpechtTreeStore` and `SpechtTreeGenerator`
  are production code in the engine, in `Specht.Tree` (ADR-0010 § "The
  layout"). The generator is an instance registered in `AddSpechtEngine()`,
  and the synthetic specification rendering ships inside `specht.tool`. The
  benchmark project declares none of the four and generates no specification
  of its own.
- C-7 is amended: a fixture's specifications are generated by the engine's
  generator, and one generated by code the benchmark project declares is ruled
  out. A copied fixture and consumer source stay ruled out.
- `0109-F2` C-11 is amended: the four types are not a benchmark-only seam. Any
  other type or member in `src/` whose only caller is a benchmark still is.
- B-015 and B-016 stay in this Feature, Active, their text and scenarios
  unchanged. They are proven by the tests of the production types under
  `test/tests/Tree/`, and no test names a type of the benchmark assembly.
- OQ-5 is resolved by the move.

## Why

- The owner ruled the tree production code, and that a benchmark measures
  production code and carries no test of its own (pull request #114).
- ADR-0010 § "What 'no static' covers" rules out a public static that
  computes, so `SpechtTree.Of` cannot move as written; the owner chose a
  generator instance over keeping the static or leaving generation in the
  benchmark project.
- The owner's "move only" ruling of 2026-11-01 leaves the engine's load on the
  tree to a later stage, so no engine consumer satisfies C-7 or C-11 as they
  stood; both are amended instead.
- B-015 and B-016 state the fixture the measuring Features need (§ 2 row 5;
  decision 0004). Moving the code that builds it does not move that need, and
  both claims read true of the engine's generator.

## Rejected

**Withdraw B-015 and B-016 and restate them in the engine's Feature,
`0001-F1`.** Two ids retired and two taken in a specification an open pull
request edits, for a claim no consumer of the check has: the engine's Feature
is about checking a tree, not generating one. Cost of rejecting: the claims'
specification sits in `.performance/benchmarks/.spec/`, apart from the code at
`src/specht/Tree/`.

**A Feature of its own for `src/specht/Tree/`.** A second agreement for one
need, holding only these two claims. Cost of rejecting: as above.

## Affects

- `0109-F1` B-015, B-016 (§ 9), C-7, § 5 row 9, OQ-5; § 6 rows 8 to 12, § 7
  `### The tree generator` and § 8 follow, by their owners.
- `0109-F2` C-11.
- `0109-F3` C-3: unchanged; the measured check still reads a tree on disk,
  saved by the store before the measurement.

## Reversal

None.
